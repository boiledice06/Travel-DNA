## 질문과 방법

고정된 서울 여행을 끝까지 같은 순서로 재생할 수 있는지, 실제 서비스에 영향을 주지 않는지 검증합니다. 전체 목적 문장과 5개 설문값을 동시에 만족하는 이전 확정 세션을 찾지 못해 동일한 조건으로 실제 API를 다시 호출했습니다. 한 세션의 응답과 해당 후보의 사진 조회 결과를 사용했습니다. 서버가 부여한 세션과 프로필 ID만 치환했습니다.

- 데이터 버전은 `presentation/final/fixtures/recording.json`의 version 1입니다. 사진은 `media.json`의 SHA-256으로 식별합니다.
- 입력, 질문과 답변, 페이로드 및 API 응답 시간은 녹화 파일에 있습니다. 장소는 기존 앱의 15곳 상한과 3일 배정 규칙을 그대로 따릅니다.
- 반복 실행마다 새 발표 초기화와 새 브라우저 저장 문맥을 사용합니다. 참가자·방문 순서·분석·이미지 응답의 동등성 및 다른 입력 거절을 비교합니다. 알고리즘에 무작위 시드는 없으며 세션 분리용 브라우저 식별자는 실행마다 다릅니다.
- Windows PowerShell, Node 22, Expo SDK 58, Microsoft Edge, Playwright, FFmpeg와 Pillow를 사용했습니다. 재현 명령은 [운영 안내](../../presentation/final/RUNBOOK.md)에 있습니다.
- 실제 모드 회귀는 다른 브라우저 문맥과 별도 실제 세션에서 수행했습니다. 이 회귀 결과는 발표 fixture에 합치지 않았습니다.

## 해석 범위

반복하는 것은 관찰된 1개 추천과 기존 앱의 일정입니다. 사례 1개의 실제 추천 품질을 전반적으로 판단하기 위한 실험은 아닙니다. 지도 타일 가용성은 인터넷과 OpenStreetMap의 운영에 의존합니다. Android 번들 생성과 실기기 실행은 서로 다른 검증 항목으로 기록합니다.
