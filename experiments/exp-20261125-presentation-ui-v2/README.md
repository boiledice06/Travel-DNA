## 목적과 가설

같은 여행 흐름에서 정보 구조를 바꾸고 실제 응답 상태에 연결한 모션을 넣어도 기존 추천과 로컬 기록이 작동하는지 확인했다. 드래그가 진행 중일 때 패널 위치가 변하고, 드래그 후 세 가지 높이로 돌아가며, 목록 또는 지도 이동과 충돌하지 않는지를 픽셀 위치와 화면 상태로 판정했다. 비교 화면은 같은 브라우저 크기와 검증용 응답을 사용했다.

## 재현 조건

- Windows, Edge Chromium, Expo SDK 58.0.22, React Native 0.88.1, React 19.3.0, Node 22.21.0. Reanimated 4.7.1과 Gesture Handler 3.3.0, Worklets 0.13.0은 설치된 SDK 번들 버전과 일치했다.
- Expo Web을 export하고 Playwright가 결과 파일을 브라우저에 전달했다. 모바일 뷰포트는 375×812, 390×844, 430×932이며 브라우저 컨텍스트마다 저장소를 분리했다.
- 고정 fixture에는 합성 여행 조건, 설문 5개, 대화, 취향 키워드와 장소 9개가 있다. 스크립트에 고정했으며 난수 시드는 사용하지 않았다. 입력 오류 복구는 첫 대화 요청에 HTTP 502 한 건을 주입했다. 실제 앱 코드는 fixture를 포함하지 않는다.
- 실제 실행은 기존 FastAPI 가상환경과 설정을 사용했다. 브라우저의 요청을 검증 스크립트에서 로컬 FastAPI에 전달했으며 서버 응답을 그대로 반환했다. 명시적으로 실패한 요청에는 제한된 횟수의 재시도를 실행했다. 외부 결과의 순서와 내용은 시점과 요청에 따라 달라진다.
- 실제 사진과 지도 타일은 장소 응답과 앱의 기존 출처를 사용했다. 기기의 여행 기록 추가·수정·삭제 검증에는 테스트 컨텍스트의 합성 레코드만 사용했다.

## 관찰과 한계

화면과 물리 위치, HTTP 상태, 버튼과 탭의 상호작용을 관찰했다. 가독성과 시각 계층의 개선은 비교 캡처에 대한 설계 판단이다. 사용자 연구, 성능 통계, 실제 추천 적합도나 네이티브 응답시간은 측정하지 않았다.
