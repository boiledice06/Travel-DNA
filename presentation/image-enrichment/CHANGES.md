# 백엔드 안정화와 장소 사진 보강

## Gemini와 요청 중복

- FastAPI의 기존 502 응답은 여러 공급자 실패의 공통 외부 코드였다. 이전 검증에는 Gemini의 upstream 503이 502로 전달된 사례가 있다. 이번 사전 검사에서 6.5초 서버 기한은 Gemini 400을 재현했고, 14초와 기본 기한은 성공했다. 서로 다른 두 관찰을 구분해 기록했다. [이전 실제 통합 검증](../../verification/FINAL_INTEGRATION_REPORT.md) · [Google 오류·재시도 안내](https://ai.google.dev/gemini-api/docs/troubleshooting)
- 애플리케이션이 SDK 내부 재시도를 한 번 호출로 설정한다. 일시적인 서버 오류 또는 연결 실패만 0.35초, 0.7초에 최대 0.12초 jitter를 더해 재시도한다. 호출당 서버 기한은 12초이며, 다음 시도까지 포함한 27초 예산을 점검하고 최대 3회로 제한한다. 요청 한도, 인증, 모델 설정, 잘못된 JSON 응답은 별도 유형이다. 읽기 타임아웃은 원래 호출의 처리 여부가 불분명할 수 있어 자동 재시도 대상에서 제외했다.
- 진행 중 같은 채팅과 추천 요청은 현재 FastAPI 프로세스에서 한 번 실행한다. 채팅은 앱이 같은 입력을 다시 보낼 때 같은 키를 사용하고, 성공 응답을 5분간 돌려줄 수 있다. 진행 중 다른 채팅 입력은 409로 응답한다. SDK 오류 전문·인증값 대신 분류, HTTP 상태, 시도 번호와 시간을 기록한다.

- 관광사진 정보는 공공데이터포털 15101914에서 **활용신청** 후 해당 서비스에 승인된 키를 백엔드 `.env`의 `TOUR_PHOTO_API_KEY`에 설정한다. 서비스별 승인 상태는 공공데이터포털에서 확인한다. 설정 후 서버를 재시작하면 엔진이 이 공급원을 조회한다.
- 별도 `/api/place-photos`는 앱이 추천을 적용한 뒤 화면 표시와 별도로 4곳씩 호출한다. 서버는 동시 실행 4개·대기 포함 12개, 배치 6초와 공급원 요청 2.5초를 사용한다. 성공 메타데이터는 24시간, 확정 미매칭은 15분, 단기 공급원 오류는 20초 동안 메모리에 캐시한다. 같은 사진 조회 작업은 동시 중복 실행을 피한다.
- 사진 보강 결과는 기존 장소 ID에 선택적으로 붙인다. 장소 점수, 추천 ID 순서, 일정 배정, 직선 연결선을 그대로 사용한다. 기존 사진 URL은 호환성과 측정에 남겨 두며 화면은 검증된 사진 메타데이터가 있을 때 표시한다.

## 화면과 남은 제한

미술관·박물관·공원·카페·음식점·건축물·거리에는 크기에 따라 다시 그려지는 벡터 일러스트가 있다. 사진이 없거나 로딩에 실패하면 **일러스트**로 표시된다. 세부 화면에서 사진 출처와 라이선스, 변경 금지 여부를 보여 준다. 검증된 사진은 추천 카드와 지도 패널, 여행 일정 썸네일에 사용한다.

짧은 취향 대화는 제목·메시지·입력란을 가운데에 묶고, 대화가 길면 메시지 영역을 스크롤할 수 있게 했다. 취향 확정의 DNA 그래픽은 넓은 색면과 더 큰 파형을 사용하며 실제 키워드가 뒤이어 등장한다. 기존 Reduce Motion 처리와 추천 대기·지도 모션을 사용한다.

TourAPI가 저작자를 제공하지 않은 항목은 미표기로 남겼다. 공급 데이터에서 공식 이미지 URL과 콘텐츠 ID는 확인했으며 사진별 공개 소개 페이지는 일부 공급원에서 제공되지 않는다. 웹에서 측정한 캐시와 로딩 결과는 한 머신과 두 일정에 대한 관찰이다. Android 번들 및 기기 검증은 별도 항목에 기록했다.
