# Edge 발표 모드 복구

2026-11-25 Asia/Seoul · 기존 기준 커밋 aee164b.

## 확인한 원인 범위

수정 직전 8785에서 받은 HTML과 JS는 당시 발표 빌드의 `__common-169eddf70e6c91b3013840be5dceb0f9.js`를 제공했고, 해당 모듈에는 발표 빌드 플래그가 true로 들어 있었다. 실제 서비스용 이전 빌드의 `__common-690e613314242363307507e2e460bc31.js`에서는 false였다. 이전 구현은 올바른 bootstrap이 있어도 false인 번들에서는 발표 모드를 켜지 않았다. 문제를 본 브라우저 탭의 당시 번들 응답은 확보하지 못해 그 탭에서 어떤 번들이 실행되었는지는 확인할 수 없다.

## 수정과 검증

- 루트로 접속하면 시나리오 선택으로 이동한다. 선택한 유형의 설정은 Expo 시작 스크립트 앞에 주입된다. 런타임 설정을 검증해 발표 모드와 동일 출처의 시나리오별 API를 설정한다.
- 이전 빌드는 `--serve-only` 실행 시 포트를 열기 전에 거부됐다. 새 HTML이 참조한 시작 JS 세 개를 직접 내려받아 디스크 산출물과 바이트 일치를 확인했다. 확인한 빌드 식별자는 `cc32c9d192a9`이며 앱 정적 파일은 `no-store`로 응답한다.
- Expo 클라이언트 환경 변수 인라인을 끈 빌드에서 현재 Edge 프로필로 루트 진입을 확인했다. 화면을 표시한 Edge 검증 창에서 A와 B를 각각 실행했다. A 전체 지도는 15곳 및 서버 추천, 상세는 국립중앙박물관 전통염료식물원 실제 사진을 표시했다. B 전체 지도는 15곳 및 서버 추천, 상세는 공근혜갤러리 실제 사진을 표시했다. 두 경우 모두 발표 표시와 사진 출처가 있었다.
- 초기 HTML에서 bootstrap을 제거했을 때 초기화 오류 화면이 표시됐고, 복구 버튼은 선택 화면을 열었다.
