# Travel DNA 구현 및 검증 보고

검증일: **2026-10-13 (Asia/Seoul)**. 환경: Windows, PowerShell, Node 22.21.0, npm 11.8.0.

이 보고는 당시 SDK 57 환경에 대한 과거 기록입니다. 현재 프로젝트는 SDK 58로 변경되었으므로 아래 결과를 현재 버전의 실기기 검증으로 해석하면 안 됩니다.

2026-11-02 추가 확인: 별도 폴더에서 SDK 58 의존성을 설치하고, React Native 0.88.1과 React 타입 19.3으로 조정한 뒤 TypeScript 검사 및 Expo 의존성 호환성 검사를 통과했습니다. 기존의 14개 추천·데이터 테스트도 SDK 58 설치 환경에서 통과했습니다. SDK 58 실기기 실행은 확인하지 않았습니다.

## 구현 완료

- Expo 57.0.28 / React Native 0.86.3 / React 19.2.3 / TypeScript strict / Expo Router 프로젝트.
- 온보딩, 닉네임, 데모 시작, 과거 경험 추가·수정·삭제.

- 설명 가능한 점수, 다른 취향의 실제 순위 변화, 계산 속성에 근거한 설명.
- 서울 8곳 / 부산 4곳의 지도 마커, 검색, 필터, 도시 전환, 현재 위치 요청.
- Compact / Expanded 추천 패널, 카드 및 지도 선택 동기화, 상세 연결.

- AsyncStorage 복원, 쓰기 순서 큐, 스키마 검사, 저장/복원 실패 안내.
- 플랫폼별 지도 분리, 이미지 대체 화면, 빈 결과, 주요 동작의 접근성 레이블.
- 공통 테마, 기능별 디렉터리, 라우트/화면/계산/저장 분리.
- README, AGENTS, APK 준비 설정, 실기기 체크리스트.

## 실제 수행한 자동 검증

| 항목                                                         | 결과와 범위                                                                      |
| ------------------------------------------------------------ | -------------------------------------------------------------------------------- |
| npm run typecheck                                            | 통과: UI와 테스트의 strict TypeScript                                            |
| npm test                                                     | **14 / 14 통과**                                                                 |
| npm run format:check                                         | 통과: Prettier                                                                   |
| npx expo install --check                                     | SDK 로컬 호환 맵 기준 의존성 일치. 샌드박스에서 원격 버전 조회가 꺼진 조건이었음 |
| npx expo-doctor@latest                                       | 네트워크 허용 환경에서 **21 / 21 통과**                                          |
| npx expo export --platform android --output-dir dist-android | Android 코드 경로와 Hermes bytecode 생성 성공                                    |
| npx expo start --web --port 8081 --localhost                 | 개발 서버 구동 및 실제 브라우저 접속 성공                                        |

Android export는 APK 빌드 또는 Android 실기기 실행이 아닙니다. 최초 샌드박스 export는 Hermes 임시 파일 쓰기 권한 오류가 발생했고, 동일 명령을 호스트 권한 환경에서 재실행해 성공했습니다.

Node의 TypeScript 테스트 실행에서 MODULE_TYPELESS_PACKAGE_JSON 경고가 발생합니다. ES module 자동 감지에 관한 경고이며 테스트는 정상 통과했습니다.

## 테스트에서 확인한 계약

1. 데모 시작이 개인 기록과 저장 장소를 보존함.
2. 반복 데모 시작이 기록을 중복 생성하거나 수정된 기록을 덮어쓰지 않음.
3. 직접 시작을 다시 진행해도 남아 있는 데모 기록의 출처 표시를 유지함.
4. 무기록 프로필은 중립 50점이며 계산값이 유한함.
5. 산책/건축 취향과 맛집/현지 취향의 추천 1위가 달라짐.
6. 광장시장의 혼잡 기피 적용 시 100점에서 65점으로 감점됨.
7. 동일 기록의 중복 태그가 가중치를 부풀리지 않음.
8. 만족도가 여러 기록의 상대 선호에 반영됨.
9. 설명의 선호/기피가 실제 계산 데이터에 존재함.
10. 서비스 응답 및 동점 정렬이 결정적임.
11. 장소 ID가 유일하고 도시별 좌표 범위가 맞음.
12. 저장 직렬화/복원이 기록과 저장 장소를 보존함.
13. 손상 JSON/잘못된 별점/중복 기록 ID를 거부함.
14. 데이터 어댑터가 잘못된 속성 강도/좌표/중복 장소 ID를 거부함.

## 브라우저에서 실제 조작한 항목

390 × 844 모바일 뷰포트의 인앱 브라우저에서 확인했습니다.

- 첫 온보딩 → 데모 DNA → 지도.
- 닉네임 입력 → 초기 기록 화면 → DNA → 지도.
- 경복궁 마커 선택 → 카드가 3 / 8로 이동 → 저장 → 상세 → 지도 복귀.
- 저장 필터: 경복궁 한 곳만 지도와 카드에 표시.
- 자연/풍경 필터: 해당하는 서울 장소 3곳으로 변경.
- 확장 추천 목록과 축소 카드 확인.
- 필터가 걸린 상태에서 광장시장 검색 → 필터 해제 → 광장시장 선택 및 카드 8 / 8 이동.
- 부산 전환: 서울 마커가 사라지고 부산 4곳만 표시.
- 새로고침 후 닉네임/도시/북마크 복원. 저장 목록의 경복궁 확인.
- 검증용 미식 여행 경험 추가 → 만족도/태그/메모 저장 → 이름/별점/기피 수정.
- 해당 경험 추가 후 맛집 선호가 0 → 44, 현지 경험이 44 → 89로 재계산.
- 검증용 경험 삭제 확인창 및 삭제 후 목록에서 제거. 생성한 테스트 기록만 제거함.
- 코드 수정 후 확장 패널 버튼의 검색창 겹침 해소 및 긴 장소명 표시 확인.

브라우저 오류 로그에 앱 런타임 오류는 관찰하지 않았습니다. 초기 FadeIn의 웹 native driver 경고는 플랫폼 분기로 수정했습니다. 검사 범위 밖의 모든 런타임 조건을 보장하는 결과는 아닙니다.

## 부분 구현

- 지도/사진의 오류 대체 UX는 구현했으나 네이티브 SDK 장애 및 오프라인 복구 전체를 실기기에서 재현하지 않았습니다.
- 위치 권한 요청과 거부/타임아웃 처리는 구현했으나 실기기 GPS 허용/거부 테스트는 하지 않았습니다.
- CSV/JSON 연결은 변환된 행 배열 검증 어댑터까지입니다. 원시 CSV 파서/업로드 UI는 없습니다.
- FastAPI는 서비스 인터페이스까지입니다. 실제 HTTP 클라이언트/서버는 없습니다.
- APK는 EAS preview 설정과 지도 키/서명 안내까지입니다. APK 생성은 하지 않았습니다.
- 사진은 여행 분위기 참고 이미지입니다. 실제 장소별 사진과 프로토타입 이미지에 근거한 정밀 디자인 재현은 포함하지 않았습니다. 제공된 첨부에는 요구사항 텍스트만 있었습니다.
