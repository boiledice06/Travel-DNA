# 서울 3일 통합 작업 보고

검증일: 2026-11-17 (Asia/Seoul). 브랜치: `codex/seoul-three-day-integration`.

## 현재 상태

이 작업은 **부분 구현**이다. 실제 서버를 조사하고 HTTP로 확인했지만, 서버 취향 분석 UI와 추천 요청의 종단 간 연결은 완성되지 않았다. 제공된 백엔드는 여행 기간으로 `half_day`, `full_day`, `1n2d`만 받아 3일을 정확하게 표현할 수 없다. `3d`를 전송한 실제 HTTP 요청은 422였다. 이를 `1n2d`로 조용히 바꾸지 않는다. 서버 URL이 설정된 상태에서 기존 제안 계약 `/recommendations`을 호출하지 않도록 지도 요청을 막고 설명한다. `src/services/backend/client.ts`는 실제 엔드포인트용 클라이언트와 shortlist 어댑터의 기반이며, 화면과 연결되지 않았다. 자동 재시도와 세션 영속화도 미구현이다.

## 변경 내용

- Intro에 서울 3일과 취향 기반 가치 제안을 표시하고 기존 직접 시작/데모 경로를 보존했다. 직접 시작은 여전히 기존 닉네임/경험 온보딩으로 이어진다.
- 지도 홈은 서울만 표시하며 기존 부산 저장 데이터는 삭제하지 않는다. 여행 조건 모달에는 서울, 3일, 전체 예산, 인원 및 동행과 목적 입력이 있다. 조건은 영속화되지 않으며 데모 추천 및 일정에 반영되지 않는다.
- 추천 패널에 collapsed/compact/expanded 상태를 추가하고 손잡이 드래그와 탭으로 전환한다. 상태는 임시 UI 상태다. 새 제스처의 실기기 검증은 필요하다.
- `src/services/itinerary/index.ts`는 서울 좌표 및 ID를 검증하고 상위 최대 15개 후보에서 멀리 떨어진 세 지점을 시드로 선택한 뒤 각 날짜의 마지막 장소와 가까운 후보를 균형 있게 배정한다. 인접 거리의 근사는 직선거리이며, 시간·도로·영업·비용을 고려하거나 보장하지 않는다. 입력이 부족하면 빈 날짜 또는 부족한 장소 수가 그대로 남는다. 사용자 조건과 카테고리 편중은 아직 반영되지 않는다.
- 지도와 카드에 날짜/순서를 표시하고 좌표 직선을 그린다. 실제 도로 경로가 아니다. 날짜별 선택과 전체 보기를 제공한다. 일정은 복원되지 않는다.
- 서버 어댑터는 유효한 서울 좌표, 이름, 제공자 및 외부 ID가 있는 후보만 수용하고 중복을 제외한다. 점수는 변환하지 않으며 없는 사진·추천 근거를 만들지 않는다. 이 어댑터는 테스트됐지만 앱의 요청에 연결되지 않았다.

## 실제 백엔드 조사 및 HTTP 확인

첨부 ZIP을 기존 코드와 분리된 `.codex-temp/backend-bundle`에 풀고 Python 의존성을 설치해 Uvicorn을 로컬로 실행했다. OpenAPI에서 `/api/trip-profile`, `/api/dna-chat/start`, `/likert`, `/message`, `/constraints`, `/finalize`, `/api/seoul-find`를 확인했다. `/api/seoul-find`는 profile_id와 확정된 dna_session_id를 받아 shortlist를 반환한다. 제공 모델의 장소에는 lat/lng, place_id, source, source_keyword 등이 있고 score는 앱의 예상 일치도와 다르다.

실제 HTTP 결과: health 200, OpenAPI 200, 프로필 생성 200 (`1n2d`), `3d` 프로필 422, 설문 시작 200 및 5문항, 응답 제출 200 및 asking/선택지, 잘못된 세션 404, 잘못된 JSON 422. 인증 없이 대화 메시지 502, 장소 검색 키 없이 503. Vertex 인증과 Google Places 키가 없으므로 실제 LLM 응답과 외부 장소 추천 성공은 검증하지 못했다. 빈 shortlist, 일부 좌표 누락은 로컬 어댑터 단위 테스트이며 실제 외부 API 응답이 아니다. 응답 지연과 서버 미연결은 기존 제안 계약의 테스트가 있으나 신규 클라이언트에 대한 별도 검증은 남아 있다.

백엔드는 별도 프로세스로 실행해야 하며 웹에서는 `CORS_ALLOW_ORIGINS`에 프런트엔드 출처를 설정해야 한다. API 키와 Vertex 인증은 서버 환경에만 둔다. `EXPO_PUBLIC_RECOMMENDATION_SERVER_URL`에는 공개 서버 기본 URL만 사용한다. 현재 앱은 실제 서버 연동이 완성되지 않아 이 변수를 설정해도 추천이 동작하지 않는다.

## 검증과 남은 작업

- `npm run typecheck`: 통과.
- `npm test`: 21개 통과. 저장 복원 및 순수 일정/shortlist 검사 포함.
- `npm run format:check`: 통과 (마지막 문서 추가 전 검사).
- `npx expo-doctor@latest`: 19/20 통과. 기존 설치된 Expo 및 관련 9개 패키지가 검사 시점 권장 버전과 다르다. 패키지는 임의로 변경하지 않았다.
- Android 및 Web export 성공. 실제 브라우저 조작, Android/iOS 실기기 및 Expo Go는 검증하지 않았다. Export는 실기기 테스트가 아니다.
- 미구현: 여행 생성 단계의 조건 입력/영속화, 3일 서버 계약 합의, 서버 DNA 설문·대화·제약·확정 UI, 프로필과 세션 저장·복구, 실제 shortlist 연결 및 재시도, 조건을 반영한 일정, 날짜별 일정 저장, 네이티브 지도/패널 조작 검증. 서버 운영자가 3일 지원을 추가한 뒤 서버 스키마와 종단 간 흐름을 다시 검증해야 한다.

기존 사용자 경험·북마크 저장 스키마는 변경하지 않았다. 첨부 백엔드와 테스트 산출물은 임시 폴더에 남아 있으며 원본 ZIP은 수정하지 않았다.
