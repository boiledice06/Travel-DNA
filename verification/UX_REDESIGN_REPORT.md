## 원인과 변경

- 관찰: TourAPI `searchKeyword2`의 `firstimage`가 후보 모델과 shortlist에 복사되지 않았고, 클라이언트 `adaptShortlist`는 이미지를 빈 문자열로 고정하며 저장 검증도 빈 문자열만 허용했다. 이미지 로드 실패 시 `Photo`는 대체 화면을 제공한다.
- TourAPI 후보의 `firstimage`를 공식 호스트 HTTPS URL에 한정하여 보존하고, 기존 이름 완전 일치 + 120m 이내 또는 주소 일치 병합 규칙을 통과한 카카오 후보에만 이어 준다. shortlist, 저장 스냅샷 및 상세 출처 표시를 연결했다. `detailImage2`는 아직 구현/검증하지 않았다. 이미지 호스트 URL에 대한 HTTPS 변환이 항상 가능한지는 입증되지 않았다.
- 공식 검색에서 국립중앙박물관 전통염료식물원, 초전섬유·퀼트박물관, 환기미술관의 이미지 URL에 대해 HTTP 200과 image/jpg 응답을 확인했다. 이는 서버 측 HTTP 검사이며 **브라우저 이미지 렌더링 성공의 증거는 아니다**. 사진이 비어 있는 실제 결과도 관찰했다. CORS와 브라우저 mixed-content 실제 사진 렌더링은 미검증이다.
- [공공데이터포털 국문 관광정보 서비스](https://www.data.go.kr/data/15101578/openapi.do?recommendDataYn=Y)는 제공 사진의 이용 관련 설명과 제한을 안내한다. 상세에 한국관광공사 출처를 표시했다. 개별 사진의 권리 표시·추가 조건은 별도 검토 필요.
- 지도 검색과 원형 옵션, 접이식 여행 조건/카테고리, 시트 내 Day 선택, 양 플랫폼 마커 텍스트 최대 폭, 탭 명칭 및 최근 서버 일정 화면을 추가했다. 서버 DNA 세션에서 확인 가능한 키워드·조건과 로컬 기록 기반 DNA를 구분한다. 기존 데이터는 삭제하지 않았다.

## 테스트와 한계

- `npm run typecheck` 통과; `npm test` 26개 통과; 백엔드 `.venv` Python pytest 51개 통과 (신규 이미지 경로·병합 테스트 포함).
- `npm run format:check`는 기존부터 수정된 `README.md`, `PROJECT_STATE.md`의 포맷 경고로 실패. 이 파일들을 일괄 포맷하지 않았다. `expo-doctor`는 npm 레지스트리 DNS 접근 실패로 실행하지 못했다. Android export는 성공했으나 마지막 필터 변경 전 수행되어 재검증이 필요하다.
- 전체 Gemini→카카오/TourAPI→3일 일정 흐름은 이번 변경 후 재실행하지 않았다. 기존 보고서의 이전 성공은 이번 코드의 성공 증명이 아니다.
- 서버 추천 장소에는 로컬 속성 벡터가 없어 기존 필터가 결과를 비울 수 있었다. 이후 서버가 반환한 검색 카테고리 텍스트에 한정한 키워드 매칭을 추가했다. 일부 카테고리는 정보가 부족해 결과가 없을 수 있으며 실제 화면 검증이 필요하다. 오류 재시도 UI는 복원했으나 화면 재검증이 필요하다. 선택 마커의 카메라 안전 영역과 접근성 reduced motion도 미완료다.
- `detailImage2`, 개별 사진 이용 조건, 카테고리 기반 fallback 개선, 브라우저에서 3개 실제 사진, 요청된 11개 PNG와 실제 터치/네이티브 검증이 남아 있다. 현재 완료 판정을 내릴 수 없다.
- Google Drive 동기화: 미완료/미검증. 기존 산출물과 비밀정보는 업로드하지 않았다. 정리 또는 삭제는 하지 않았다.
